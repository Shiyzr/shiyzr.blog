## 流程回顾
1. 先搞到一堆训练数据（正常人话就行）。
2. 选一套切分方案（比如 BPE，或者别的 tokenizer），根据这套方案，构建一个词汇表，用来把 token（字符串形式）映射到一个个整数 ID。
3. 用词表和 tokenizer 把原始文本啃一遍，变成一长串 ID 序列。
4. 把这些 ID 序列丢给模型（例如一个 Transformer），反复训练，最后得到一个“见过世面”的语言模型。

## Step 2
搞定“切词方案”BPE

思考方法前先明确一下我们的目标：
- 简而言之，就是设计一个函数，输入是原始文本，输出一个词汇表，形如：
```
{ 
  ...
  "7418": "Ġfirmly",
  "7419": "ounce",
  "7420": "ĠLaura",
  "7421": "fly",
  "7422": "Ġshown",
  "7423": "Ġfamiliar",
  "7424": "Ġthorns",
  "7425": "Spike",
  "7426": "ĠWo",
  "7427": "Ġdrawers",
  "7428": "child",
  "7429": "ĠZee",
  ...
}
```
为了获得这个词表，我们的整体思路如下：
1. 先构建一张初始词汇表。
2. 遍历训练数据，统计每个字符对出现的频率。
3. 合并出现频率最高的字符对，加入词汇表。
4. 重复步骤2和3，直到词汇表大小达到预设值。

那就开始
### 1. 先构建一张初始词汇表
选取什么样的字符作为初始词汇表很重要，因为我们需要尽可能适配所有的字符，包括英文、中文、数字、标点符号甚至表情符号等等。

我们可能会想到ASCII编码，但是ASCII编码只有128个字符，远远不够。

然后有一种神奇的编码方式，它可以涵盖所有的字符，包括中文、日文、韩文、表情符号等等，甚至是一些特殊字符（如换行符、制表符等）。

这个编码方式叫做UTF-8，它是一种变长编码，每个字符占用1到4个字节，根据字符的不同而变化。

那我们就不如以byte为单位，直接令初始字符集为所有可能的字节值（0到255）。

但是，最后还有一点要注意：对于一些**Special Token**，它们是一些具有特定功能、不代表普通语义文字的特殊符号，像是一组“信号灯”或“控制指令”，告诉模型如何处理文本的边界和结构。我们需要单独处理，不参与BPE合并。

比如`<|endoftext|>`, `[PAD]`等
```python
    # Initialize vocab with special tokens
    for token in special_tokens:
        vocab[next_id] = token.encode("utf-8")
        special_token_map[token] = next_id
        next_id += 1
    
    # Map raw bytes to IDs
    byte_to_id = {}
    for i in range(256):
        vocab[next_id] = bytes([i])
        byte_to_id[i] = next_id
        next_id += 1
```

### 2. 遍历训练数据，统计每个字符对出现的频率
为了防止乱合并，我们引入了一个**预分词**的操作，就是基于一个规则先将语料拆成一些词，再做BPE。

比如：
```
PAT = r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"""
```
> 那我们为什么不直接用这套规则拆词呢，还要BPE干啥。

预分词流程：
```
# 定义正则模式（防止跨越空格/标点合并）
正则 PAT = GPT2 官方切分规则

# 读取输入文件
读取 整个文本字符串

# 初步切分
使用 特殊标记 作为分隔符，将全文切成 文本块(chunks)

# 统计词频
新建 词频字典 word_counts (键是ID序列, 值是频率)
对于 每个文本块:
    如果 是特殊标记:
        记录其 ID 序列，频率 +1
    否则 (普通文本):
        根据 正则 PAT 进一步切分成 单词列表
        对于 每个单词:
            将单词转为 字节序列
            再转为 基础字节ID序列 (利用 byte_to_id)
            在 word_counts 中累加该 ID序列 的出现次数
```
> 注意：这里我们建立了一个**词频词典**，用于降低时间复杂度。
> 
> 你想啊，每次合并新的字符对时，都需要遍历所有的单词对，检查是否有新的合并机会。
> 
> 但是，如果我们提前统计好词频，就可以直接根据词频来判断是否合并，而不需要每次都遍历所有单词对。

为了高效地找到哪两个 ID 最经常挨在一起，建立索引。
```
新建 统计字典 stats (键是(ID1, ID2)对, 值是总出现次数)
新建 索引字典 indices (键是(ID1, ID2)对, 值是包含该对的“词”在列表中的下标集合)

# 将 word_counts 转换为列表形式以便快速修改
words = [ID序列列表]
counts = [对应的频率列表]

对于 每个词及其对应的下标 i:
    对于 词中的每一对相邻 ID (pair):
        stats[pair] += 该词的频率
        indices[pair] 添加 下标 i
```


```
新建 合并记录列表 merges

循环 直到 词表大小 达到 预设的 vocab_size:
    # 1. 找冠军
    从 stats 中找到 出现频率最高 的 ID对 (best_pair)
    (如果频率相同，按 ID 的字母顺序排序选择)
    如果 找不到 或 频率为0，退出循环

    # 2. 注册新 ID
    记录合并操作: (ID1内容, ID2内容) 加入 merges
    创建 新字节内容 = 内容1 + 内容2
    在 vocab 中存入: {next_id: 新字节内容}
    new_token_id = next_id
    next_id 累加 1

    # 3. 局部更新 (为了效率，只更新包含 best_pair 的词)
    获取 所有包含 best_pair 的 词下标集合 words_to_update
    删除 stats 和 indices 中关于 best_pair 的旧记录

    对于 集合中的每个 词下标 idx:
        获取 旧词序列 和 频率
        
        # A. 扣除旧贡献
        遍历旧词中所有的 相邻ID对:
            在 stats 中减去该词频率
            在 indices 中移除该词下标
        
        # B. 执行合并逻辑 (如 [1, 2, 3] 中合并 1,2 变为 [new, 3])
        按顺序遍历旧词，发现 (best_pair[0], best_pair[1]) 就替换为 new_token_id
        更新 words[idx] 为 新词序列
        
        # C. 增加新贡献
        遍历新词中所有的 相邻ID对:
            在 stats 中加上该词频率
            在 indices 中添加该词下标

返回 最终词表 和 合并规则
```
